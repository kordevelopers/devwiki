# LightningBar 분석 기반 개선/확장 제안서

## 1. 분석 요약
현재 `LightningBar`는 다음 강점이 있습니다.

- 옵션 객체 그룹화(`TitleOptions`, `Legend`, `Bars`, `NoData` 등) 구조가 잘 잡혀 있어 확장성이 좋음
- 런타임 변경 API(`UpdateOptions`) 제공으로 화면별 커스터마이징이 쉬움
- NoData 표시 모드(기존/오버레이)와 워터마크 스타일 옵션이 이미 존재
- RawData 버튼, 이미지 렌더링/저장 등 실무 기능이 포함되어 있음

반면, 실사용 관점에서 아래 항목은 개선 여지가 큽니다.

- 옵션이 많아지면서 “필수/권장/고급” 구분이 부족함
- 렌더링/레이아웃 계산이 단일 클래스에 집중되어 유지보수 난이도 상승
- 카테고리 라벨, NoData, 레전드가 서로 영역 충돌할 가능성 있음
- 테스트 자동화(렌더링 회귀) 체계가 문서/코드로 명확히 보이지 않음

---

## 2. 우선 개선 제안 (High Priority)

## 2.1 옵션 검증 레이어 추가
### 제안
`LightningBarOptions.Validate()` 또는 내부 정규화 메서드로 옵션 유효성 검사를 명시화.

### 이유
현재도 `Math.Max` 등으로 방어는 하지만, 잘못된 설정이 들어왔을 때 원인 파악이 어려움.

### 예시 항목
- `BadgeBackOpacity`는 0~255 강제
- `FixedHeight > 0`, `ReferenceSeriesCount >= 1`
- `Legend.LabelMaxLines >= 1`, `CategoryLabels.MaxLines >= 1`

---

## 2.2 레이아웃 충돌 방지(자동 재배치)
### 제안
타이틀/레전드/NoData/RawData 버튼의 충돌 여부를 계산해 자동으로 위치 보정.

### 이유
화면 크기/글자수/폰트가 달라지면 요소가 겹칠 수 있음.

### 최소 구현
- 렌더링 전 사전 측정(Measure pass)
- 각 요소에 안전 영역(safe area) 적용
- 겹침 시 우선순위 기반으로 위치 이동

---

## 2.3 NoData 동작의 의미 분리
### 제안
NoData 상태 판단 규칙을 enum으로 세분화.

### 후보
- `MissingOnly` (데이터 배열 없음)
- `AllZeroAsNoData` (모든 값 0 포함)
- `CustomPredicate` (사용자 콜백)

### 이유
도메인별로 “0은 데이터 없음인지” 해석이 다름.

---

## 2.4 렌더링 책임 분리
### 제안
`LightningBar` 내부 렌더링을 기능별 클래스로 분리.

### 예
- `TitleRenderer`, `LegendRenderer`, `NoDataRenderer`, `AxisRenderer`, `BarRenderer`

### 이유
기능 추가 시 기존 로직 영향 최소화, 디버깅/테스트 용이.

---

## 3. 중기 개선 제안 (Medium Priority)

## 3.1 테마 프리셋 지원
### 제안
`LightningBarTheme`(Light/Dark/Pastel/HighContrast) 제공.

### 이유
다수 차트를 빠르게 통일감 있게 생성 가능.

---

## 3.2 접근성(Accessibility) 강화
### 제안
- 색약 친화 팔레트 옵션
- 대비(contrast) 자동 검사/경고
- 키보드 포커스 가능한 인터랙션(바 탐색)

---

## 3.3 라벨 엔진 강화
### 제안
- 자동 줄바꿈/말줄임 정책 선택
- 카테고리 라벨 회전 각도(0/45/90)
- 긴 문자열 툴팁 표시

---

## 3.4 성능 최적화
### 제안
- 측정 결과 캐시(폰트/문자열)
- 변경 없는 레이어 재렌더링 생략
- 대량 데이터 시 단순화 렌더링 모드

---

## 4. 추가하면 좋은 기능 (Feature Ideas)

1. 기준선/목표선(Threshold line) 표시
2. 범례 클릭으로 시리즈 show/hide
3. 축 값 포맷터(delegate)
4. 바 정렬/스택 모드(Clustered/Stacked)
5. 애니메이션(초기 로드, 데이터 갱신)
6. Export 확장(PDF/SVG)
7. 차트 상태 직렬화(JSON preset)
8. 통합 이벤트(`ChartRendered`, `NoDataShown`)

---

## 5. 테스트/품질 제안

## 5.1 렌더링 회귀 테스트
- 기준 이미지 스냅샷과 픽셀 비교(허용 오차 기반)
- 케이스: 정상 데이터 / AllZero / Missing / 긴 라벨 / 작은 화면

## 5.2 옵션 조합 테스트
- 모드 조합 매트릭스
- 예: NoData 모드 × 라벨 방향 × 레전드 정렬

## 5.3 샘플 시나리오 강화
- 동적 문서 샘플에 “실시간 옵션 토글” 패널 추가
- NoData 모드 비교 버튼(기존/오버레이)

---

## 6. 권장 실행 순서

1. 옵션 검증 레이어 도입
2. 레이아웃 충돌 자동 보정
3. NoData 규칙 enum 세분화
4. 렌더링 클래스 분리
5. 테마/접근성/성능 기능 순차 도입

---

## 7. 결론
현재 구조는 이미 실무 사용 가능한 수준입니다. 다만 앞으로 기능이 더 늘어날 계획이라면, **옵션 검증 + 레이아웃 안전성 + 렌더링 책임 분리**를 먼저 수행하는 것이 유지보수성과 확장성 측면에서 가장 효과적입니다.
