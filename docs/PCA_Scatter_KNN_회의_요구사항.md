# PCA Scatter 및 유사 실험 추천 요구사항

> 작성일: 2026-06-22
> 근거: 회의 메모 사진 5장 (`Photo 1.jpg` ~ `Photo 5.jpg`)
> 상태: 회의 메모 기반 요구사항 정리본. 아래의 `확인 필요 항목`이 결정된 후 개발 기준선으로 확정한다.

## 1. 목적과 범위

- 과거 실험 데이터를 조회하고, 각 실험의 JSON 데이터를 전처리한다.
- 전처리한 고차원 수치 데이터를 PCA로 2차원 축소한다.
- PCA 결과를 Scatter 차트에 표시한다.
- 차트의 각 점은 하나의 실험(`Draft_NO`)을 나타낸다.
- 사용자가 특정 `Draft_NO`를 선택하면 KNN으로 가장 유사한 실험 3건을 찾는다.
- PCA와 KNN은 동일한 전처리 결과와 동일한 `StandardScaler`를 사용하여 좌표와 거리 계산의 일관성을 보장한다.

## 2. 용어 및 식별자

| 용어 | 의미 |
|---|---|
| `Draft_NO` | 실험을 식별하는 고유 ID |
| `target_draft.No` | 사용자가 유사 실험 검색 대상으로 선택한 `Draft_NO` |
| `X1` | PCA 제1주성분. 가장 큰 분산을 설명하는 축 |
| `X2` | PCA 제2주성분. 두 번째로 큰 분산을 설명하는 축 |
| `AI_RSLT_Val` | 실험 결과 구분값. 회의 메모 기준 `Pass` 또는 `Review` |
| `Similar_Draft` | 대상 실험과 유사한 실험의 ID |
| `Distance` | 표준화된 수치 행렬에서 계산한 유클리드 거리 |

## 3. 입력 데이터 요구사항

### 3.1 데이터 조회

1. 과거 실험 데이터 전체를 조회한다.
2. 조회 데이터는 JSON 형식이다.
3. 각 실험 JSON에는 약 80개 또는 80개 이상의 데이터 항목이 포함되는 것으로 메모되어 있다.
4. JSON에서 `Draft_NO`를 먼저 분리한다.
5. `Draft_NO`는 식별자로 사용하며 PCA/KNN의 수치 특징에는 포함하지 않는다.
6. JSON의 나머지 항목 중 수치형 데이터만 특징값으로 추출한다.

### 3.2 JSON 변환

- JSON 문자열을 사전/목록 구조(`Dict`/`List`에 해당하는 구조)로 변환한다.
- 구현 언어가 C#인 경우에도 동일한 논리 구조를 사용하며, 특정 JSON 라이브러리에 종속시키지 않는다.

## 4. 전처리 요구사항

전처리는 모든 실험에 동일한 컬럼 순서와 동일한 규칙으로 적용한다.

1. 숫자형(`Number`) 컬럼만 추출한다.
2. 상수 컬럼을 제거한다.
3. 분산이 `1e-10`보다 작은 컬럼을 제거한다.
4. 모든 실험 데이터에서 동일한 값을 갖는 컬럼을 제거한다.
5. 제거 후에도 모든 실험의 특징 벡터 길이와 컬럼 순서가 같아야 한다.
6. 남은 수치 행렬에 `StandardScaler`를 적용한다.
7. 정규화 결과는 컬럼별 평균 `0`, 표준편차 `1`을 기준으로 한다.
8. 학습된 `StandardScaler` 객체와 특징 컬럼 목록을 PCA와 KNN이 함께 사용한다.

## 5. PCA 요구사항

### 5.1 알고리즘

- 알고리즘: PCA(Principal Component Analysis)
- 입력: 정규화된 수치 행렬
- 옵션: `n_components = 2`
- 출력: 각 `Draft_NO`에 대한 2차원 좌표 `X1`, `X2`

### 5.2 좌표 의미

- `X1`: 제1주성분이며 가장 큰 분산을 설명한다.
- `X2`: 제2주성분이며 두 번째로 큰 분산을 설명한다.
- PCA 결과는 과거 실험 데이터를 2차원으로 축소하여 시각화하는 데 사용한다.

## 6. Scatter 차트 요구사항

### 6.1 점과 시리즈

- 각 실험(`Draft_NO`)을 하나의 점으로 표시한다.
- 점의 좌표는 `(X1, X2)`이다.
- 결과는 `Pass`, `Review` 두 그룹만 구분하여 표시한다.
- 그룹 구분값은 `AI_RSLT_Val`을 사용한다.

### 6.2 축과 범위

- X축 라벨은 `X1`로 표시한다.
- Y축 라벨은 `X2`로 표시한다.
- 각 축에는 실제 PCA 좌표의 최솟값과 최댓값 범위를 반영한다.
- 실제 좌표값의 범위를 화면에 표기한다.
- 그리드와 기준점 `(0, 0)`을 표시 범위에 포함한다.
- 기존 프로토타입의 X/Y축 `1~100` 고정 범위는 이번 회의 요구사항과 맞지 않으므로 그대로 사용하지 않는다.

### 6.3 상호작용

- 점에 마우스를 올리면 해당 실험의 라벨을 표시한다.
- 라벨에는 최소한 `Draft_NO`가 포함되어야 한다.
- 선택한 점을 기준으로 유사 실험 검색을 실행할 수 있어야 한다.

## 7. KNN 유사 실험 추천 요구사항

### 7.1 목적

- 사용자가 선택한 특정 실험(`target_draft.No`)과 수치적으로 가장 유사한 실험 3건을 탐색한다.
- 사용자 입력값은 `Draft_NO`이다.

### 7.2 입력

- PCA 전처리에 사용한 것과 동일한 정규화 수치 행렬을 입력으로 사용한다.
- PCA와 동일한 `StandardScaler` 객체 및 동일한 특징 컬럼 순서를 사용해야 한다.
- KNN 거리는 PCA 2차원 좌표가 아니라 표준화된 원본 특징 공간에서 계산하는 것으로 정리한다.

### 7.3 알고리즘 옵션

| 옵션 | 값 |
|---|---|
| 알고리즘 | KNN |
| `metric` | Euclidean distance(유클리드 거리) |
| `n_neighbors` | `4` |
| `algorithm` | `auto` |

- `n_neighbors = 4`는 대상 실험 자신을 포함한 값이다.
- 데이터 크기와 특성에 따라 `auto`가 `ball_tree` 또는 `kd_tree` 등을 자동 선택하도록 한다.

### 7.4 검색 절차

1. 전체 데이터에서 입력한 `Draft_NO`의 정확한 인덱스를 찾는다.
2. 대상 실험과 전체 데이터셋 사이의 거리를 계산한다.
3. 거리가 짧은 순서로 정렬한다.
4. 거리 `0`인 자기 자신을 제외한다.
5. 남은 결과 중 상위 3건을 선택한다.

### 7.5 추천 결과

| 컬럼 | 설명 |
|---|---|
| `Rank` | 유사도 순위 `1`, `2`, `3` |
| `Similar_Draft` | 유사 실험 ID |
| `Distance` | 유클리드 거리. 소수점 넷째 자리까지 표시 |

## 8. 결과 데이터 구조

회의 메모에 기재된 기본 데이터 테이블 컬럼은 다음과 같다.

| 컬럼 | 용도 |
|---|---|
| `Draft_NO` | 실험 ID |
| `X1` | PCA 제1주성분 좌표 |
| `X2` | PCA 제2주성분 좌표 |
| `AI_RSLT_Val` | `Pass`/`Review` 결과 구분 |
| `Distance` | 선택한 대상 실험과의 거리 |

PCA 좌표 테이블과 KNN 추천 결과를 분리하는 경우에도 위 필드가 손실되지 않아야 한다.

## 9. 예외 처리

- 존재하지 않는 `Draft_NO`를 입력하면 경고를 표시하고 다시 입력할 수 있게 한다.
- 유사 실험 후보가 3건보다 적으면 오류로 중단하지 않고 존재하는 개수만 반환한다.
- JSON 파싱 실패, 수치 변환 실패, 필수 식별자 누락은 처리 결과에서 명확히 구분할 수 있어야 한다.
- 전처리 후 유효한 수치 컬럼이 2개 미만이거나 PCA 계산이 불가능한 경우 사용자에게 원인을 표시해야 한다.
- 특정 실험에 컬럼이 누락되어도 전체 특징 컬럼 순서가 바뀌어서는 안 된다. 누락값 처리 정책은 개발 전에 확정한다.

## 10. 일관성 요구사항

- PCA와 KNN은 같은 원본 데이터 스냅샷을 사용한다.
- 수치 컬럼 선별 및 상수 컬럼 제거 결과를 공유한다.
- 동일한 `StandardScaler` 인스턴스의 변환 결과를 공유한다.
- PCA 좌표를 다시 계산하거나 KNN을 실행할 때 컬럼 순서가 변경되지 않아야 한다.
- 동일 입력 데이터와 동일 옵션에 대해서 PCA 좌표와 KNN 추천 결과가 재현 가능해야 한다.

## 11. 개발 수용 기준

1. 실제 JSON 데이터에서 `Draft_NO`와 수치 특징을 분리할 수 있다.
2. 비수치 컬럼과 분산 `< 1e-10`인 상수 컬럼이 PCA/KNN 입력에서 제외된다.
3. 표준화 결과가 평균 `0`, 표준편차 `1` 기준에 맞는다.
4. PCA가 각 실험에 대해 `X1`, `X2`를 생성한다.
5. Scatter 차트가 실제 좌표 범위와 원점 `(0,0)`을 포함해 표시된다.
6. 점의 마우스 오버 라벨에서 `Draft_NO`를 확인할 수 있다.
7. 차트가 `Pass`, `Review` 두 그룹만 구분한다.
8. 특정 `Draft_NO`를 선택하면 자신을 제외한 최근접 실험 최대 3건이 반환된다.
9. 추천 결과가 `Rank`, `Similar_Draft`, 소수점 넷째 자리의 `Distance`를 제공한다.
10. 존재하지 않는 `Draft_NO`와 데이터 부족 상황이 요구사항대로 처리된다.
11. PCA와 KNN이 같은 scaler와 특징 컬럼을 사용한다.

## 12. 기존 구현과 달라지는 점

현재 `PcaScatterSampleForm`은 실제 PCA 계산이 아닌 랜덤 분포를 사용하는 프로토타입이다. 이번 회의 요구사항을 적용할 때 다음 변경이 필요하다.

| 기존 프로토타입 | 회의 요구사항 |
|---|---|
| 랜덤 샘플 생성 | 실제 과거 실험 JSON 조회 및 전처리 |
| PCA 계산 없이 임의 좌표 생성 | `StandardScaler` + PCA(`n_components=2`) 계산 |
| `Fail`, `Pass`, `Insufficient` 3시리즈 | `Pass`, `Review` 2시리즈 |
| X/Y축 `1~100` 고정 | 실제 PCA 좌표 범위 표시 및 원점 포함 |
| 단일 점 상세 표시 | 점 선택 후 KNN 유사 실험 3건 제공 |

기존 Scatter 공통 컨트롤의 배경, 폰트, 범례, 줌 비활성화, 툴팁 및 이벤트 기능은 가능한 한 유지하고 PCA/KNN 데이터 처리 계층을 별도로 추가한다.

## 13. 확인 필요 항목

아래 내용은 사진에서 의미가 완전히 확정되지 않았거나 구현 정책 결정이 필요한 항목이다.

1. `약 80개`와 `80개가 넘는 데이터`가 실험별 JSON의 필드 개수인지, 전체 실험 행 개수인지 확인이 필요하다. 문맥상 수치 특징 개수로 보인다.
2. JSON의 누락값, `null`, `NaN`, 무한대 및 수치 문자열 처리 방식을 정해야 한다.
3. PCA 모델/scaler를 조회마다 다시 학습할지, 저장된 모델을 불러올지 정해야 한다.
4. `AI_RSLT_Val`이 정확히 `Pass`/`Review` 문자열인지, 별도의 값을 두 그룹으로 매핑하는지 확인이 필요하다.
5. 기본 데이터 테이블의 `Distance`를 모든 행에 표시할지, 선택한 대상과 추천 결과에만 표시할지 결정해야 한다.
6. 축 여백 비율과 원점 포함 방식은 정해야 한다. 원점 때문에 실제 데이터가 한쪽에 몰리지 않도록 최소 여백 정책이 필요하다.
7. 사진 3 하단의 `기타` 메모는 글씨가 흐려 정확한 문구 판독이 어렵다. 선택점 또는 산점 위치를 함께 표시하는 요구로 보이므로 원문 확인이 필요하다.
8. 메모에는 `Draft_NO`, `Draft_No`, `draft_No`, `target_draft.No` 표기가 함께 사용되었다. 데이터 컬럼과 API의 표준 이름을 `Draft_NO`로 통일할지 확인해야 한다.
9. 중복된 `Draft_NO`가 조회될 경우 오류 처리, 첫 행 선택 또는 복수 행 처리 중 어떤 정책을 사용할지 정해야 한다.

## 18. 데이터베이스 ACT_DATA 연동

### 18.1 조회 동작

- `ScatterMain` 상단의 `DB 조회` 버튼으로 실행한다.
- 조회 SQL 기본값은 `SELECT ACT_DATA FROM AI_INFERNECE`이다.
- 조회는 UI가 멈추지 않도록 백그라운드 작업에서 실행한다.
- 결과 행이 하나여도 되고 여러 행이어도 된다.
- 각 행의 `ACT_DATA`가 비어 있거나 전체 결과가 없으면 사용자에게 오류를 표시한다.
- DB 조회 중에는 검색, DB 조회, 샘플 재생성 컨트롤을 비활성화한다.
- 조회와 분석이 모두 성공한 경우에만 기존 차트 데이터를 교체한다.

### 18.2 연결 설정

실제 연결 문자열은 비밀번호 노출을 방지하기 위해 소스 코드에 넣지 않는다. 배포 환경의 `LightingChartSamples.exe.config` 또는 개발 환경의 `App.config`에서 다음 값을 설정한다.

```xml
<connectionStrings>
  <add name="AiInferenceDatabase"
       connectionString="실제 연결 문자열"
       providerName="System.Data.SqlClient" />
</connectionStrings>
```

쿼리와 timeout은 `appSettings`에서 변경할 수 있다.

```xml
<add key="PcaActDataQuery" value="SELECT ACT_DATA FROM AI_INFERNECE" />
<add key="PcaActDataCommandTimeoutSeconds" value="30" />
```

### 18.3 ACT_DATA JSON 처리

`ActDataJsonParser`는 JSON 문자열을 `Dictionary<string, object>`와 `IEnumerable` 구조로 변환한 후 `Draft_NO`가 있는 실험 객체를 찾는다.

지원하는 구조:

- 단일 실험 객체: `{ "Draft_NO": "...", ... }`
- 실험 배열: `[{ "Draft_NO": "..." }, ...]`
- wrapper 목록: `{ "data": [{...}], "items": [{...}] }`
- JSON 문자열 안에 다시 들어 있는 이중 인코딩 JSON
- 중첩 객체와 숫자 배열

중첩 값은 다음과 같이 평탄화한다.

```text
Measurements.Temperature
Measurements.Pressure
Vector[0]
Vector[1]
```

파싱 오류에는 `ACT_DATA[index]`를 포함하여 어느 DB 결과에서 문제가 발생했는지 표시한다. `Draft_NO`가 없는 객체는 PCA/KNN의 식별자로 사용할 수 없으므로 명확한 오류로 처리한다.

## 19. Oracle Exadata CONV_EXPER_CTN 연동

### 19.1 운영 조회 기준

- 대상 테이블: `TASADM.PCCB_INFER_RSLT_INF`
- 판정 테이블: `TASDEV.PCCB_JUDGE_RSLT_INF`
- JSON 컬럼: `CONV_EXPER_CTN`
- 조회 기간: `M.CHG_TM > SYSDATE - 10`
- JOIN: `M.DRAFT_NO = J.DRAFT_NO AND M.PARAM_TYP = J.PARAM_TYP`
- `J.ENGR_RSLT_VAL IS NOT NULL`인 행만 사용한다.
- DB 행 하나를 PCA 실험 한 건으로 사용한다.
- 식별자는 `M.DRAFT_NO`, 모집단은 `M.PARAM_TYP`, Y 라벨은 `LABEL_Y`를 사용한다.
- `CONV_EXPER_CTN` 배열에는 해당 행의 실험 객체가 한 건 들어 있다.
- 시작 시 샘플 데이터는 생성하지 않는다.
- 지원 PARAM_TYP는 `RESPONSE`, `DEFECT`, `EPM`, `PROBE`이며 현재 UI에는
  `RESPONSE`, `DEFECT`만 표시한다.

### 19.2 Draft_NO 검색과 좌표계 일관성

1. 새로고침 정책에 따라 Exadata를 조회하거나 정상 메모리 스냅샷을 사용한다.
2. 선택된 `PARAM_TYP`의 행만 PCA 모집단으로 필터링한다.
3. 모집단에서 입력한 `DRAFT_NO`를 먼저 검색한다.
4. Draft가 없으면 PCA를 실행하지 않고 기존 차트와 스냅샷을 유지한다.
5. JSON에서 `PUB_NO`, `_VERSION_NM`과 문자열을 제외하고 숫자 특징만 추출한다.
6. 단일 `StandardScalerModel`로 모집단 전체를 한 번 표준화한다.
7. 같은 scaler 객체와 표준화 행렬로 PCA 좌표와 KNN 거리를 생성한다.
8. 검색 결과에는 원본 JSON, 평탄화 값, 숫자 특징, 표준화 벡터와 X1/X2를 보관한다.

따라서 선택한 `Draft_NO`의 좌표와 전체 데이터의 좌표는 같은 PCA 좌표계에 있고,
KNN 거리도 그 분석에서 생성된 같은 표준화 특징 공간을 사용한다.

### 19.3 데이터 무결성 처리

- 대상 Draft의 NULL, 빈 JSON 또는 빈 배열은 `실험 데이터가 없습니다`로 처리한다.
- 다른 행의 실험 데이터가 없으면 PCA 모집단에서 제외하고 누락 건수를 표시한다.
- 잘못된 JSON은 `CONV_EXPER_CTN[index]`를 포함한 오류로 처리한다.
- JSON 배열에 객체가 두 건 이상이면 데이터 구조 오류로 처리한다.
- 같은 `PARAM_TYP`에서 중복된 `DRAFT_NO`는 오류로 처리한다.
- 전체 조회와 분석이 성공한 경우에만 기존 차트 결과를 교체한다.
- `AlwaysReload`는 조회마다 DB를 호출하고 `PreferMemorySnapshot`은 정상 스냅샷을
  우선 사용한다.
- 실제 Exadata 접속은 운영 연결 문자열과 ODP.NET provider가 필요하므로 개발
  저장소에서는 빌드 및 JSON 분석 경로까지만 검증한다.

### 19.4 시연 데이터와 조회 포인트 강조

- `가상 데이터` 버튼은 Exadata 연결 없이 RESPONSE/DEFECT 시연 데이터를 생성한다.
- 가상 데이터도 운영과 동일한 행 모델, JSON 파서, StandardScaler, PCA, KNN을 사용한다.
- 기본 가상 데이터는 RESPONSE 30건, DEFECT 30건, 각 실험당 수치 특징 80개다.
